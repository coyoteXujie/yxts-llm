# 白金英雄坛说 — 交付标准与施工手册（给 AI 协作者）

> 这份文件是硬约束，不是参考。每一轮开工前先完整读一遍，再动手。
> 目标只有一个：**让一个陌生人愿意为它掏 10 美元**。除此之外的"进度"都不算进度。

---

## 0. 之前为什么失败

不是能力问题，是标准问题。以下是已经发生的事实，不要再重复：

1. 会话里宣布过"游戏现在可以卖钱了"，被追问后被自己推翻，并承认**从来没真正跑过一次游戏**——一直在加功能、改数据、生成图片。
2. 用户实机启动，第一分钟就 `SCRIPT ERROR`（`get_rarity_color`、`CORE_RUMOR_NPCS` 未定义）。崩溃是**用户发现的**，不是测出来的。
3. 73 个区域里有 46 个的背景是纯色横带占位图。其中包含**七大门派里 6 个**。
4. 412 条未跟踪文件、34 个文件改了没提交、161MB 资源不在仓库里；`export_presets.cfg` 被 `.gitignore` 排除，所以"导出预设就绪"在仓库里根本不存在。
5. 唯一的自动化流程测试 `godot_project/tests/playtest_flow.tscn` 在 headless 下运行超过 9 分钟无任何输出（等于挂死），所以"验证通过"没有依据。

结论：**不能用"我做了什么"汇报进度，只能用"别人能验证到什么"汇报进度。**

## 1. 现状判决（以数据为准）

### 1.1 画面质量分层（致命）

依据 `godot_project/data/stage_layer_assets.json` 指向的实际 PNG 文件体积：

| 层级 | 区域数 | 说明 |
|---|---|---|
| A 手绘级 | **1**（平安镇） | 三层合计约 2.6MB，DNF 风格精绘街景 |
| B 可接受 | **26** | 三层合计 170KB–715KB，风格化生成图，勉强能看 |
| C 占位级 | **46** | 三层合计 **26KB–32KB**，本质是几条纯色横带 + 几个白色圆圈/方块 |

C 层里包括：巩义、偃师、孟津、凤翔、咸阳、渭南、临潼、余杭、嘉兴、绍兴、双流、新都、温江、夷陵、当阳、嵩山、黄河谷地、太行、钟条山、秦岭深处、终南、中原森林、渭河、陇西沙漠、华山、潼关、临潼温泉、江南水泽、武夷、洞庭、钱塘潮、天目山、太湖、黄山、绍兴水乡、嘉兴运河，以及**八卦门、红莲教、那迦派、太极门、雪山派、逍遥宫**六大门派。

后果：玩家从平安镇（精绘）走到巩义镇（纯色块），3 秒内判定"这是半成品"。主线和七派入门任务都要经过这些区域，所以这条路线上的观感断层是**发行级阻断问题**。

根因：`tools/batch_generate_stage_assets.py`、`tools/batch_generate_stage_assets_v2.py`、`tools/gen_stage_v3.py` 这类程序化批量生成脚本，被用来"补齐"73 个区域的背景数量。**用数量冒充质量，是这次失败的主因。**

### 1.2 其他已确认问题

- 新游戏流程存在脚本错误（已修但未验证）。
- 方向键无法移动。
- 460 条区域连接、151 个任务、183 个物品、146 个 NPC 均已通过 `tools/validate_godot_data.py`——**数据不是问题，体验和观感才是问题**。

## 2. "有人愿意掏 10 美元"的可验收定义

把它当成一份合同。以下 9 条全部满足，才算达标：

1. **冷启动零门槛**：陌生人拿到压缩包，双击就能玩，不需要命令行、不需要装引擎、不需要改配置。
2. **连续 30 分钟零故障**：不崩溃、不卡死、不出现空白面板、不需要重启。允许的报错数为 0。
3. **前 15 分钟没有任何一眼假的素材**：不出现纯色块背景、白圆圈云、方块树、未描边的占位图。
4. **有牵引**：玩家任何时候都知道"我现在该去哪、为什么去"。HUD 或任务日志必须给出可执行的下一步。
5. **有节奏**：开场 30 秒内给到画面 + 声音 + 一个明确目标。
6. **有高潮**：至少有一个"值得截图发给别人"的瞬间（战斗、场景、演出任选）。
7. **有结束**：哪怕是章节结尾，也要有收束和字幕，不能是无限循环或断头。
8. **感官完整**：全程有 BGM，交互和战斗有音效，不是默片。
9. **可验证**：上面 8 条每一条都要有"别人照着做就能复现"的验证步骤。

反面定义——以下一律**不算**进度：数据条目数量、文档字数、脚本数量、生成图片数量、代码行数、"已完成 XX 模块"的自我描述。

## 3. 铁律

1. 一次只做一件事。除非事先说明理由，单轮修改文件数 ≤ 5。
2. 声称"完成"必须附四样：改了哪些文件、跑了什么命令、命令**原始输出**、别人可独立复现的验证步骤。缺一不可，没有命令输出等于没完成。
3. 禁止把"新增数据 / 新增文档 / 新增生成脚本"当作进度。
4. **禁止再用程序化批量生成充当美术。** 具体点名：`tools/batch_generate_stage_assets.py`、`tools/batch_generate_stage_assets_v2.py`、`tools/gen_stage_v3.py` 及其全部产物。背景图必须是接近平安镇质量的实际绘制/图像生成结果，做不到就砍掉那个区域。
5. 视觉相关改动必须附截图证据（改前/改后）。
6. 改数据或资源后必须跑 `python3 tools/validate_godot_data.py` 和 headless 启动，且输出零 `ERROR`、零 `ObjectDB` 泄漏。
7. 改场景、脚本或资源路径后必须跑一次 headless 启动验证。
8. 一件事做完立刻用明确路径 `git add` 并提交，一个任务一个提交，message 写"做了什么 + 怎么验证"。禁止留下几十个文件的大散改。
9. 禁止新增 `tools/generate_*.py` / `batch_generate_*.py`。
10. 禁止往 `README.md` 和 `docs/14` 的进度表里新增"已完成"结论；进度描述必须由脚本从 `godot_project/data/*.json` 统计生成。
11. 半成品功能只有两个出路：做完并验证，或者删干净。不允许留在工作区里。
12. 不确定就先报告，给判断和证据，等确认再动手。禁止"先改了再说"。
13. 禁止使用"预计""应该可以""理论上""基本完成"这类措辞描述产物状态。
14. `AGENTS.md` / `CLAUDE.md` 里的命令必须始终是当前机器上**真的能跑通**的命令；跑不通就立刻修文档并说明。

## 4. 里程碑与硬验收

### M0 · 止血（先做，其余全部延后）

目标：让"存在的东西"是能稳定跑通的。

任务：
1. 修好新游戏流程的脚本错误，并验证。
2. 修好方向键/移动。
3. 修好 `playtest_flow`（或重写一个能在 headless 跑完的 smoke 测试），使其成为可用门禁。
4. 清理工作区：34 个未提交文件按"可提交 / 半成品删除"分类处理，一次一提交。
5. 清理 412 条未跟踪文件：保留有效资源并提交，删除 v1/v2/v3 批次垃圾。
6. 修正 `AGENTS.md` / `CLAUDE.md` 里跑不通的命令。

验收：
- 从主菜单开始，走完"新游戏 → 序章 → 建角色 → 进平安镇 → 与 NPC 对话 → 接一个任务 → 打一场战斗 → 存档 → 读档 → 退出"，全程零 `SCRIPT ERROR`。**必须贴出完整日志。**
- headless 启动零 `ERROR`、零 `ObjectDB` 泄漏。
- `git status` 只剩有意义的改动，未跟踪条目 ≤ 50。

### M1 · 前 15 分钟（决定留存）

目标：陌生人前 15 分钟不会想关掉。

任务：开场画面化（序章现在只有黑底文字）、角色创建补预览图、第一个任务加位置指引、HUD 不遮挡角色、战斗结算不卡空白面板。

验收：录一段 15 分钟从头开始的连续视频（或逐帧截图），中途无一次故障、无一处占位素材。

### M2 · 收敛范围（关键决策，需人类拍板）

目标：宁可小而精，不要大而烂。

做法：只保留平安镇 + 3～5 个相邻区域作为正式内容，其余区域从世界地图和任务链中**优雅下线**（不是删除数据，是不让玩家走到）。

理由：10 美元买的是观感密度和完成度，不是区域数量。8 个漂亮场景 > 73 个纯色块。

验收：玩家可达区域内，A/B 级背景覆盖率 100%，C 级背景出现次数 0。

### M3 · 视听统一

目标：从"能玩"到"好看好听"。

任务：`audio_manager.gd` 真正接线（BGM/音效/环境音）、UI 统一皮肤、战斗动作与特效。

验收：全程有声音；随机截 5 帧画面，风格一致，看不出占位。

### M4 · 发行

目标：能交到别人手上。

任务：可用的导出配置、能双击运行的产物、商店页素材（截图/GIF/文案）。

验收：找 3 个没看过这个项目的人，只给压缩包，不做任何提示，观察 15 分钟。要求：3 人都能自己进入游戏，且没有人主动退出。

## 5. 每轮交付格式（照抄）

```
任务：<一句话，只写一件事>
验收标准：<可执行命令 + 期望输出>
限制：只允许修改 <文件或目录>
交付：diff 摘要 + 命令原始输出 + 我手动复现的步骤
```

回复必须包含：

1. 本次只做了什么（一句话）。
2. 改了哪些文件及原因。
3. 跑了什么命令，**原始输出贴出来**。
4. 人类如何手动复现验证。
5. 还有什么已知问题（不许隐瞒）。

## 6. "假完成"识别表

| 你会说的话 | 检查方式 |
|---|---|
| "已实现/已完成" | 对应哪个文件、哪一行？玩家在哪一步能感知？ |
| "验证通过" | 贴命令原文和输出。 |
| "可以卖钱了" | 按第 2 节 9 条逐条自评，缺一条就是不能。 |
| "背景已覆盖 73/73" | 列出每个文件体积。小于 100KB 的三层背景一律按占位处理。 |
| "测试通过" | 测试在 headless 下能跑完吗？跑完了贴输出。 |
| "数据已扩展" | 玩家能感知到哪一处变化？ |
