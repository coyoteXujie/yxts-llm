## 0. 先看这次事故：为什么第一条规则是"别把成果弄丢"

2026-09-29 00:39:47，工作区被整体回退到 HEAD。

核查结果：

| 项目 | 回退前 | 回退后 |
|---|---|---|
| 已修改未提交文件 | 34 个（约 10110 行新增） | 0 个 |
| NPC / 物品 / 任务 | 146 / 183 / 151 | 112 / 98 / 60 |
| 舞台背景区域数 | 73 | 27 |
| get_rarity_color 等修复 | 存在 | 已消失 |

恢复核查：`git reflog` 只有一条 clone 记录，`git stash list` 为空，`git fsck --dangling` 无悬空对象，索引与 HEAD 一致。
结论：这批未提交改动不可恢复。

这就是铁律「改完立刻提交」的真实代价。在没有提交之前做任何清理动作，都等于把工作扔掉。

## 1. 绝对禁止（违反一次就停止迭代，等人类处理）

1. 禁止 `git checkout -- .`、`git restore .`、`git reset --hard`、`git clean -fd`、`git stash drop`，以及任何丢弃未提交改动的操作。
2. 禁止在"未提交"状态下清理工作区。要清理，先 `git add` + `git commit` 保存现状，再动手。
3. 禁止 `rm -rf` 任何目录。要删文件，先用 `git status` / `rg` 确认无引用，逐个列出路径，删完立刻提交。
4. 禁止在没有人类确认的情况下删除任何"看起来像成品"的资源（手绘 PNG、音频、字体）。
5. 禁止改写 `README.md` 和 `docs/14` 里的进度数字；进度必须由脚本从 `godot_project/data/*.json` 统计得出。

---

## 2. 一轮迭代的七个固定步骤

1. 读 `docs/17_交付标准与施工手册.md` 和本文件。
2. 从第 4 节队列里取队首未完成项，不要自己另挑任务。
3. 先复现：跑一次能暴露问题的命令，把失败原文贴出来。没有复现证据就不许开始改。
4. 只改这一件事。单轮修改文件数不超过 5 个，超出要事先说明理由。
5. 跑门禁：`python3 tools/gate.py`。
6. 在第 5 节迭代日志追加一行。
7. `git add <明确路径>` + `git commit`（一个任务一个提交），然后回到第 1 步做下一轮。

## 3. 门禁

```bash
python3 tools/gate.py          # 完整门禁：数据校验 + 占位背景 + git 卫生 + 启动 + 流程测试
python3 tools/gate.py --quick  # 只做静态自查，不能当作交付证据
```

规则：

- 门禁结果 PASS 才算完成。FAIL 时把输出原文贴出来，不许用文字描述代替。
- 门禁里的"警告"项要么修掉，要么在日志里写清为什么不修。
- 门禁本身有 bug 可以修，但不许为了让门禁变绿而放宽门禁标准。放宽标准必须在日志里写明理由并等人类确认。

## 6. 必须停下来问人类的情况

遇到以下任一情况，立刻停止本轮，不要自行决定：

1. 需要删除任何像成品的资源。
2. 需要修改 `README.md` / `docs/14` 的进度数字。
3. 需要砍区域、砍功能、砍任务（范围决策）。
4. 需要引入新的第三方依赖、下载外部资源、申请网络权限。
5. 门禁在同一处连续 3 轮 FAIL。
6. 发现有人或其他 AI 正在同一目录并发改动。
